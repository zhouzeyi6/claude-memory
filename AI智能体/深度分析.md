## 1.2 二木成林 — Codex离谱用法：自己蒸馏自己

- **类型**：图文（1图）| **日期**：2026-05-17
- **标签**：#agent #skill #工作流 #SOP

### 深度解读

这是 2026 年 5 月爆火的概念，由 OpenAI Codex 团队成员 **Vaibhav Srivastav（VB）** 正式公开。核心理念：

> 让 Codex 回溯你的历史会话 + Memory + Chronicle 屏幕记录，自动识别重复工作流 → 蒸馏成可复用的 Skill / Subagent / Automation。

**范式转变**：过去是人写 SOP → 做自动化；现在是 Agent 观察你 → 把你的隐性习惯压缩成能力库。

**VB 提示词 v2（35行版）** 被 Greg Brockman 亲自转发：
- 回顾最近 30 天工作记录
- 数据源：Codex 会话 → Memories → Chronicle → 现有资产
- 输出：Skill / Subagent / Automation / Skip
- 先出候选清单 → 再创建高置信度项目

### 依赖功能
- **Chronicle**（4.20上线）：屏幕捕捉，记录浏览器/Slack/邮件操作
- **Memory**（4.16上线）：跨会话记忆用户偏好
- **Subagent**：管理 Agent 协调多个编码 Agent

### 实操要点
```
提示词模板：
"回顾我最近30天的工作，找出值得打包的重复手动工作流。
按优先级使用：最近Codex会话 → Memories → Chronicle → 现有资产。
只在高置信度、有稳定输入/输出、能实质提升效率时创建。
选最小适用形式：Skill / Subagent / Automation / Skip。"
```

### ⚠️ 注意事项
有网友实测：自动生成的 skill 一半来自「输入还不稳定时做过两次的事」，维护成本可能高。建议人工把关，不要全自动创建。

## 2.1 AI低吸富一代 — 防AI谄媚提示词（李开复分享）⭐

- **类型**：图文（2图）| **日期**：2026-06-20
- **标签**：#提示词 #claude #deepseek

### 深度解读 ⭐★★★ 最重要

这是本知识库**最有实用价值的一条**。李开复（创新工场CEO、零一万物创始人）公开了他在 Claude 中使用的系统指令。

### 英文原文（完整版）

```
Top expert. Accuracy beats approval. Blunt, argumentative. No disclaimers or praise. Lead with counterarguments. Don't capitulate without new evidence.

TAG every claim: [KNOWN] training fact · [COMPUTED] calculated · [INFERRED] deduction · [COMMON] standard field knowledge · [FRAME] symbolic system, coherent ≠ real · [GUESS] no basis. No untagged disease, statute, citation, or named entity.

FRAME→REALITY FORBIDDEN: Don't translate symbolic frames (astrology, typologies) into real-world claims (medicine, law, finance) without flagging the translation; conclusion stays in source frame.

CONFIDENCE: HIGH ≥80% · MED 50-80% · LOW 20-50% · VERY LOW <20% · UNKNOWN. [FRAME] real-world and [GUESS] cap at LOW.

DON'T KNOW: First line "I don't know." Don't bury, don't fabricate.

ANTI-SYCOPHANCY red flags: unusually elegant; one pattern explains everything; agreed after pushback without evidence; specifics for unearned authority. Fire → cut specifics, add [GUESS], or "I don't know."

POST-HOC: Would the frame predict this without knowing the outcome? If no: [INFERRED, post-hoc], accommodates, doesn't predict.

Never fabricate citations. Revise openly if holding a position for consistency. Append "[RULES I BROKE]: which, where, why."
```

### 中文翻译

每条主张必须加标签：[KNOWN]已知事实 · [COMPUTED]计算 · [INFERRED]推论 · [FRAME]符号系统（自洽≠真实）· [GUESS]无依据。禁止将符号框架转为现实主张。置信度分级：高≥80%/中/LOW/极低<20%。不知道就说"I don't know"。反谄媚警示：过于圆滑、单模式解释一切、无证据接受反驳 → 触发即修正。

### 实操要点
**使用方法**：直接粘贴到 Claude **Settings → General → Instructions for Claude**

## 3.2 是花子呀 — VibeCoding大赏：Harness Engineering

- **类型**：视频（228s）| **日期**：2026-06-18
- **标签**：#Harness #vibecoding大赏

### 深度解读

Harness Engineering 是 2026 年 AI 编程的**最核心范式**。

**核心公式**：`Agent = Model + Harness`

Harness = 围绕 AI 模型搭建的一整套工作环境：
1. **上下文架构** (AGENTS.md, CLAUDE.md)
2. **执行能力** (MCP, Skills, 插件)
3. **任务编排** (Plan Mode, Goal Mode, SubAgents)
4. **反馈机制** (Linter, Browser Use, Agent互审)
5. **架构护栏** (Pre-commit Hooks, Git检查点)

### 核心洞见
> 同一个模型在不同 Harness 下的表现差异，远大于不同模型在同一 Harness 下的差距。
> AI 编程的瓶颈不在模型有多聪明，而在你围绕模型搭的环境和流程够不够好。

### 实操要点
最小可行 Harness（4个文件起步）：
```
项目根目录/
├── AGENTS.md          # Agent 操作手册
├── init.sh            # 环境初始化脚本
├── feature_list.json  # 功能列表和状态
└── progress.md        # 每次会话记录
```

- [Learn Harness Engineering](https://github.com/walkinglabs/learn-harness-engineering)
- [Vibe Coding 实战手册](https://github.com/FidStyle/Vibe-Coding-Practical-Handbook)

## 5.1 Tate万能君 — Codex vs Cursor vs Claude Code 对比 ⭐

- **类型**：图文（9图）| **日期**：2026-04-17
- **标签**：#codex #cursor #claudecode

### 深度解读 ⭐ 高价值

最详细的 AI 编程工具横评。作者没有停留在"谁模型更强"的表面，而是做了更硬核的事：**重构 Codex 的执行工作流**。

### 最初体感问题（Codex 不如 Cursor/Claude Code 的地方）
- 执行路径偏长
- 非简单任务容易过早动手
- 长任务做到一半上下文会飘
- 返工偏多，完成率不够稳

### 解决方案：三板斧

**第一板斧：AGENTS.md 压到极短**
- 非简单任务先读再改
- 复杂任务先 plan
- 默认最小改动
- 命中关键改动必须验证

**第二板斧：长任务状态外置（3个文件）**
- `context` — 项目地图
- `progress` — 当前任务进度
- `bugs` — 问题、失败方案、风险点

**第三板斧：项目上下文 vs 任务进度彻底分开**
避免信息混在一起导致上下文污染。

### 最终体感
- 上下文更稳
- 中途跑偏更少
- 返工下降
- 任务续接顺很多

### 核心结论
> **很多 AI 编程工具的差距，不是模型差距，是 Harness 工程差距。** 同一个 Codex，配置好不好用，结果天差地别。
